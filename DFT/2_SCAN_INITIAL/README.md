## 💡 What is Full-Scan Insertion?

In **Full-Scan DFT**, every standard sequential flip-flop in the design is replaced with a **Scan D-Flip-Flop (SDFF)**. During logic synthesis, Genus connects the scan output (`Q` or `SDO`) of each flip-flop to the scan data input (`SDI`) of the next flip-flop, forming continuous shift registers called **Scan Chains**.

```text
                                FULL-SCAN SHIFT PATH
                   +──────────────────────────────────────────+
                   │                                          │
    ScanIn_1 ─────>│ [SDFF 1] ───> [SDFF 2] ───> ... ───> [SDFF N] │─────> ScanOut_1
                   │    ^             ^                      ^    │
                   +────│─────────────│──────────────────────│────+
                        │             │                      │
    ScanEnable ─────────┴─────────────┴──────────────────────┴───── (Shift=1 / Capture=0)
    ScanClock  ────────────────────────────────────────────────────
```

### The Three Phases of Scan Testing:
1. **Scan-In (Shift Phase, `ScanEnable = 1`)**: Test stimulus vectors generated by ATPG are shifted serially into the flip-flops via `ScanIn` ports.
2. **Capture Phase (`ScanEnable = 0`)**: One functional clock cycle is pulsed. The combinational cloud processes the scan-in state, and the resulting response is captured back into the flip-flops.
3. **Scan-Out (Shift Phase, `ScanEnable = 1`)**: The captured response is shifted out via `ScanOut` ports and compared with expected golden responses on the ATE tester, while simultaneously shifting in the next pattern.

## ⚖️ Scan Architecture & Chain Balancing (80 Chains)

In this stage, we configure **80 parallel scan chains** (`chain_1` to `chain_80`):
- **Total Registers Scanned**: 8,545 flip-flops.
- **Average Chain Length**:
  $$\text{Average Length} = \frac{8,545 \text{ flops}}{80 \text{ chains}} \approx 107 \text{ flops/chain}$$
- **Why Multiple Chains?**: Having 80 parallel chains reduces the test shift time per pattern from 8,545 cycles (if 1 chain were used) down to only **~107 clock cycles**!

## 📜 Line-by-Line Script Breakdown (`scan.tcl`)

### 1. Library, HDL & Output Directory Setup
```tcl
set DESIGN_NAME "TOP"
set HDL_PATH    "../../RTL"
set SCRIPT_PATH "../../CONSTRAINTS"
set LIB_PATH    "../../../Library/timing"
set LIB_LIST    "slow.lib"
set EFFORT      "high"
set VERILOG_LIB "../../../Library/verilog/typical.v"

set WORK_DIR    "${DESIGN_NAME}_Scan"
set REPORT_DIR  "$WORK_DIR/Report"
set NETLIST_DIR "$WORK_DIR/Netlist"
set ATPG_DIR    "${DESIGN_NAME}_ATPG"

file mkdir $WORK_DIR
file mkdir $REPORT_DIR
file mkdir $NETLIST_DIR
file mkdir $ATPG_DIR
```
- Sets up working directories for synthesized netlists, timing reports, and Modus ATPG files.

### 2. Constraints Ingestion & Timing Intent Linting
```tcl
source cons.tcl
check_timing_intent -verbose > $REPORT_DIR/${DESIGN_NAME}_timing_lint.rpt
```
- Loads functional timing constraints (`cons.tcl`) and verifies that all clocks, input delays, and output delays are properly defined.

### 3. Test Signal and Test Clock Definitions
```tcl
set_db dft_scan_style muxed_scan

define_test_signal -function shift_enable -active high -create_port -default_shift_enable ScanEnable
define_test_signal -function test_mode -active high -create_port TestMode
define_test_signal -function async_set_reset -active low [get_ports RST_N]

define_test_clock -name ScanClock -function test_clock -period 20000 -controllable [get_ports REF_CLK]
```

### 4. Creating 80 Scan Chains in Tcl Loop
```tcl
set NUM_SCAN_CHAINS 80

for {set i 1} {$i <= $NUM_SCAN_CHAINS} {incr i} {
    create_port -direction in  -name ScanIn_$i 
    create_port -direction out -name ScanOut_$i 
    define_scan_chain -name chain_$i -sdi [get_ports ScanIn_$i] -sdo [get_ports ScanOut_$i]
}
```
- **Explanation**: Creates 80 primary input ports (`ScanIn_1`..`ScanIn_80`) and 80 primary output ports (`ScanOut_1`..`ScanOut_80`), then binds each pair to a named scan chain object (`chain_1`..`chain_80`).

### 5. Automated Violation Repair
```tcl
check_dft_rules
fix_dft_violations -async_reset -test_control TestMode
fix_dft_violations -async_set -test_control TestMode
fix_dft_violations -clock -test_control TestMode
```
- Cleans all DRC rule violations before gate mapping.

### 6. Logic Synthesis & Technology Mapping
```tcl
set_db syn_generic_effort $EFFORT
syn_generic

set_db syn_map_effort $EFFORT
syn_map
```
- **`syn_generic`**: Synthesizes RTL into generic gate primitives (GTECH).
- **`syn_map`**: Maps generic cells to target standard cell library gates (`slow.lib`) and replaces standard flip-flops with scan-equivalent cells.

### 7. Scan Chain Stitching
```tcl
set_db [current_design] .dft_min_number_of_scan_chains $NUM_SCAN_CHAINS
connect_scan_chains -auto_create
```
- **`connect_scan_chains -auto_create`**: Connects all 8,545 scan flip-flops serially into the 80 defined scan chains, balancing chain lengths and inserting lockup latches across clock domain crossings.

### 8. Incremental Optimization
```tcl
set_db syn_opt_effort $EFFORT
syn_opt
```
- Optimizes setup/hold timing and fixes any electrical design rule violations (max capacitance, max transition) introduced by the added scan wiring.

### 9. Exporting Netlists & Modus ATPG Database
```tcl
write_netlist > $NETLIST_DIR/${DESIGN_NAME}_Scan_Netlist.v
write_sdc >     $NETLIST_DIR/${DESIGN_NAME}_mapped.sdc
write_dft_atpg -library $VERILOG_LIB -directory $ATPG_DIR -generate_config_file [current_design]
```
- **`write_dft_atpg`**: Automatically exports everything required for Cadence Modus ATPG:
  - Gate-level test netlist (`.test_netlist.v`)
  - Pin assignment file (`.FULLSCAN.pinassign`)
  - Ready-to-run ATPG Tcl script (`runmodus.atpg.tcl`)

## 🔬 Cadence Modus ATPG Flow Walkthrough

The generated script [TOP_ATPG/runmodus.atpg.tcl](TOP_ATPG/runmodus.atpg.tcl) executes the ATPG pattern generation flow in Cadence Modus:

```tcl
# 1. Initialize Modus Database
set_db workdir TOP_ATPG
set WORKDIR [get_db workdir]

# 2. Build the Logic Model from Gate Netlist + Verilog Library
build_model \
    -cell TOP_DATA_WIDTH8_ADDR_WIDTH4_RF_DEPTH16_FIFO_DEPTH2048_FIFO_PTR_WIDTH11 \
    -techlib ../../../Library/verilog/typical.v \
    -designsource $WORKDIR/*.test_netlist.v \
    -allowmissingmodules yes

# 3. Build Test Mode (FULLSCAN) using Pin Assignment
build_testmode \
    -testmode FULLSCAN \
    -assignfile $WORKDIR/*.FULLSCAN.pinassign \
    -modedef FULLSCAN

# 4. Verify Test Structures (Scan Chain Shift Validation)
verify_test_structures -testmode FULLSCAN

# 5. Build Fault Model (Static Stuck-At Faults)
build_faultmodel -includedynamic no

# 6. Generate Deterministic Test Patterns
create_logic_tests \
    -experiment TOP_atpg \
    -testmode FULLSCAN

# 7. Write Out Verilog Parallel Simulation Testbench
write_vectors \
    -inexperiment TOP_atpg \
    -testmode FULLSCAN \
    -language verilog \
    -scanformat parallel

# 8. Commit Patterns to Database
commit_tests -inexperiment TOP_atpg -testmode FULLSCAN
```

## 🎯 Summary & Key Takeaways

1. **Full-Scan Insertion** converts complex sequential logic into simple combinational testing blocks.
2. Partitioning into **80 parallel chains** reduces test shift time dramatically.
3. `write_dft_atpg` seamlessly bridges Cadence Genus (synthesis) and Cadence Modus (ATPG).
